# Local model training • instructor kit

Open `index.html` in a browser. It is the complete illustrated workshop guide and runs without a web server or external assets. Extract the entire folder before opening links. Start with Step 01 and run terminal commands from this folder.

## Pump-history background

The guide now includes a researched background section for a fictional motor-driven auxiliary feedwater pump, AFW-P-101A: proposed history fields, four illustrative work orders, an evidence-backed answer and evaluation dimensions. This is the agreed next exercise; the runnable dataset and scripts still implement classification. The guide labels that distinction explicitly.

## What is included

- An opening graphic separating training from inference, an actual fictional training record, illustrative before/after JSON, and a five-stage interactive explanation.
- A real single-record comparison: `python scripts/predict.py data/new-record.txt --base-only`, then the same command with `--adapter runs/run01/adapter` after training. Illustrative answers in the guide are not measured model outputs.

- A 15–20 minute beginner lesson on training, inference, loss, gradients and LoRA, with discussion questions.

- 60 fictional training records, 20 development records, 20 final test records in `data/`.
- Dataset card, a new-record exercise, and expected JSON labels.
- LoRA training on Qwen2.5-0.5B-Instruct using PyTorch and PEFT.
- Identical baseline/adapter prompts and strict field-level evaluation.
- Actual local HTML report generation from your own prediction files.
- Model staging, offline loading, transfer inventory and verification instructions.
- Beginner explanations, facilitator notes, troubleshooting and participant exercises.

Model weights and Python packages are NOT included. Stage them on an approved connected Linux machine before entering a disconnected environment. This kit contains only invented administrative records and classroom routing rules; it is not a plant operating system or a validated decision aid.

## Run order after installing packages and staging the model

```bash
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1
export HF_HUB_DISABLE_TELEMETRY=1
python scripts/evaluate.py --split dev --out runs/baseline-dev.json
python scripts/train.py --out runs/run01 --epochs 3
python scripts/evaluate.py --split dev --adapter runs/run01/adapter --out runs/run01/dev.json
python scripts/compare.py runs/baseline-dev.json runs/run01/dev.json --out runs/run01/dev-report.html
# Freeze your configuration before opening the final test results.
python scripts/evaluate.py --split test --out runs/baseline-test.json
python scripts/evaluate.py --split test --adapter runs/run01/adapter --out runs/run01/test.json
python scripts/compare.py runs/baseline-test.json runs/run01/test.json --out runs/run01/test-report.html
python scripts/predict.py data/new-record.txt --adapter runs/run01/adapter
```

Scripts refuse to overwrite run/evaluation files. For another experiment use run02 and new report names. Compare baseline and adapter on the same split. Do not tune on the final test; creating new wording from test records also leaks test information.

## Validation scope

See `VALIDATION.md` for author-side checks. No training result is bundled or claimed. The GPU run must be performed in your training environment. Reports generated by compare.py contain actual model outputs from your runs. Eight scorer tests check common false-pass cases; they do not assess model quality.

## Reuse

The fictional teaching data and original workshop code/text may be reused and adapted for instruction. The Qwen model and installed libraries retain their own licenses; review them when packaging software. Keep model cards and license files in the staged model directory.
